# Codex SOL Project Manager Skill

面向 Codex 的官方模型团队管理 Skill。它只在用户明确输入“启动 SOL 总负责模式”、调用 `$sol-project-manager`，或明确要求 SOL 统筹多角色项目时启用。

本 Skill 只使用当前 Codex 实际提供的 OpenAI 模型，不接入第三方模型、本地模型服务或额外密钥。

## 工作方式

```text
用户
  ↓
SOL 主窗口：唯一总负责人，负责目标、组队、模型选择、跨窗口消息、返工和最终验收
  ↓
可见任务窗口：按能力承担产品、架构、开发、测试、研究或审查
```

### 官方定位（不是职位表）

- `gpt-5.6-sol`：GPT-5.6 旗舰模型，面向复杂推理、编码和专业工作。
- `gpt-5.6-terra`：在智能水平与成本之间取得平衡。
- `gpt-5.6-luna`：面向成本敏感、高吞吐工作负载。

产品经理、架构师、开发、测试或审查不是模型的固定职位。SOL 作为唯一总负责人和最终验收者，是本 Skill 按用户要求建立的管理制度，不是 OpenAI 对模型的官方职位定义。

运行时按六项因素选择：所需质量、问题复杂度与含糊度、失败影响、任务规模、延迟与成本、结果能否独立验证。质量或风险主导时倾向 SOL；质量与成本平衡时倾向 Terra；成本或吞吐主导且结果容易可靠验证时倾向 Luna。任务名称本身不决定模型，也不会把未知模型自动归档。

模型定位依据 [OpenAI Model Guidance](https://developers.openai.com/api/docs/guides/latest-model)，并以当前 Codex 执行面实际可用的模型和推理档为准。

## 安装

将本仓库复制到 Codex 用户 Skill 目录：

```powershell
git clone https://github.com/Aimark-dai/codex-sol-project-manager-skill.git "$env:USERPROFILE\.codex\skills\sol-project-manager"
```

如果目标目录已经存在，请先备份或改用其他目录，不要直接覆盖个人修改。

## 使用

在新项目中选择 SOL，然后输入：

```text
启动 SOL 总负责模式。

项目目标：
验收标准：
约束：
```

也可以输入：

```text
$sol-project-manager 帮我完成……
```

普通聊天、能力询问和示例讨论不会启动团队模式。明确启动后，SOL 可以按需创建可见任务窗口：简单开发默认一个执行窗口，由 SOL 验收；只有风险、专业分工或安全并行确有需要时才增加窗口。窗口逐个创建，不需要用户再次授权。

## 核心规则

- SOL 是唯一组队者和最终验收者。
- SOL 主窗口之外默认一个、最多三个可见执行窗口；新增窗口的收益必须大于 Token 与协调成本。
- 角色逐个启动并确认连接成功；出现重连提示时停止新增，只处理本轮新建角色，不影响原有工作窗口。
- 窗口间的流程消息由 SOL 转发；实现窗口和独立复核窗口分开，返工回到原实现窗口。
- 一个文件或强耦合区域同一时间只有一个写入负责人。
- 实现者不能批准自己的交付，复核意见必须回到 SOL。
- 失败先按需求、能力、容量、工具环境或文件冲突判断根因；只有能力不足才更换更合适的模型。
- 模型不可用时只在当前 Codex 明确支持且适合该负载的官方模型之间改派，不静默替换。
- 删除重要数据、发布部署、对外发送、付费、项目外访问和新密钥仍需相应授权。
- 可见窗口功能不可用时才允许降级为当前窗口或内部代理，并必须明确告知，不能冒充多窗口执行。
- 首次派发只给必要上下文；返工复用原窗口并只发增量；窗口用简短结构化结果汇报，避免重复读取、搜索、方案和测试。
- SOL 不包办 Terra 或 Luna 能可靠完成的实现；只有风险或失败证据支持时才升级模型。
- SOL 上下文显著膨胀且项目进入新阶段时，可用精简交接轮换控制窗口；新窗口接管后旧窗口停止调度，避免重复携带完整历史。

## 文件

- `SKILL.md`：触发条件、能力路由、执行原则、权限和完成标准。
- `references/team-workflow.md`：多角色任务契约、状态、返工和模型故障处理。
- `agents/openai.yaml`：Codex 界面元数据和默认启动提示。

## 验证

- 使用 Skill Creator 的 `quick_validate.py` 验证目录和元数据。
- 静态扫描确认不存在第三方模型、本地模型端口、路由配置或凭据。
- 用高风险高吞吐、工具故障、容量故障和模型质量不足场景验证路由、独立复核与根因分流。
